# Review — Phase 1 step 3 draft (web transport + phone UI, Qwen draft 1)

Reviewed against: `docs/build-briefs/PHASE1_STEP3_web_transport_ui.md` (items 1–9, §4 JSON shape, B1–B10), `docs/PROJECT_PLAN.md` §2.3/2.4/2.5/4.2/4.4/5.2/6.1, the verified step-1 baseline in `firmware/LED_Sign_Mesh/` (`docs/reviews/STEP1_VERIFICATION.md`), and the Symbol Edition UI (`firmware/legacy/LED_Sign_WiFi_Symbol_Edition.ino`). Draft read from the Qwen box at `~/esp32-led-sign/drafts/step3_qwen_v1/`; compile log `build1.log` (stopped at the first `#include`, so it under-reports by a wide margin).

Toolchain: core 3.3.12 / IDF 5.5.5, FastLED 3.10.9, ArduinoJson 7.4.3, core `WebServer`/`DNSServer`/`Preferences`. No async web libraries installed.

What the draft changed vs the verified baseline (by `diff`): **new** `transport.h`, `transport_web.h/.cpp`, `commands.h/.cpp`, `web_page.h`, `web/index.html`, `build_web.py`, `build_web.ps1`; **modified** `LED_Sign_Mesh.ino` (+38 lines). **Byte-identical to step 1**: `config.h`, `protocol.h`, `hub.h`, `hub.cpp`, `node.h`, `node.cpp`, `storage.h`, `storage.cpp`, `display.*`, `radio_espnow.*`. The draft tree also contains a stale `LED_Sign_Mesh/build/` directory (step-1 binary, 40 MB elf/map) that must not be committed.

## Verdict

**NOT MERGEABLE — 19 blocking, 16 major, 12 minor. Items 4 (per-board telemetry), 5 (node/hub styling), 7 (persistence + auto-save) and most of 3 (command semantics) are not implemented; item 2 is written against a library that is not installed and not in the brief.**

The draft does not compile for at least six independent reasons beyond the missing `ESPAsyncWebServer.h`: `storage.h` gained no `sign` namespace API yet `commands.cpp` calls nine `storage::*Sign*` functions; `hub.h` exports nothing new yet `commands.cpp`/`transport_web.cpp` reach into eight `static` hub internals; `web_page.h` (a complete array definition with include guards) is `#include`d *inside* a second array initializer; `JsonDocument&` is bound to a `JsonVariant`; `transport_web.cpp` uses `hub::`/`radio::`/`WiFi` without the headers. Once it compiles, the first thing `transport_web::begin()` does is call `WiFi.softAP(ssid, pass)` **a second time with the default channel (1)**, which moves the AP off channel 6 and makes every node deaf — a direct regression of verified A2–A6. `setCommandHandler()` is never called, so every `POST /cmd` would answer `{"ok":false,"err":"hub_only"}`. The page has a SpiderMonkey-only expression-closure syntax (`function(x) x.classList…`) on four lines, which is a `SyntaxError` in Chrome and Safari, so **no JavaScript on the page runs at all** (B8 fails at load). Swatches do not POST, sliders do not POST, `loadState()` and `#boardsCount` do not exist.

The good parts: the file split matches plan §5.1; `symbolCode()` maps all 12 tokens correctly (1–10, 13, 14); the captive-portal URL list is complete; `build_web.py` produces the brief's header format with size/sha1 comment; the page is 15.5 kB (≤ 40 kB), dark by default, has the four tabs, a working `insertSymbol()` with the correct `{token}` strings, a toast, and `focusin`/`focusout` poll pausing. These should be kept (see "Keep as-is").

## Findings

Severity: **blocking** = will not compile, regresses verified step-1 behaviour, or defeats B1–B4 outright; **major** = a brief item or B5–B10 fails; **minor** = quality/robustness.

## Refactor plan (ordered)

The hub and node changes (items 4 and 5) do not exist in the draft and must be written from scratch against the verified step-1 files. The design below is prescriptive so the refactor agent does not have to invent it.

### R1. `sign_state.h` (new, ~40 lines)
```cpp
struct SignState {               // the whole user-visible configuration, plain POD, memcpy-able
  char     text[61];             // original message, uppercased, {tokens} intact (<= 60)
  uint8_t  r, g, b;              // base colour
  bool     rainbow;              // == (effect == 3); kept for cfg JSON
  uint8_t  bri;                  // requested 0..100
  uint8_t  effect;               // 0 static 1 blink 2 fade 3 cycle
  uint16_t effectPeriodMs;       // 100..2000
  uint8_t  boards;               // 0 = auto
};
static const SignState SIGN_DEFAULT = { "HI", 0,255,0, false, 100, 0, 500, 0 };
uint8_t  signCap(const SignState& s);                 // 70 rainbow; channels>=64: 3→60, 2→80, else 100
uint8_t  signBriEff(const SignState& s);              // min(bri, cap)
void     signLayout(const SignState& s, char out[MAX_BOARDS]);   // tokens → codes, one char per pos (step 2 replaces)
char     symbolCode(const char* token);               // move from commands.cpp
const char* symbolName(char code);                    // 1..14 → "heart"… (for /state char and cfg)
const char* fxName(uint8_t fx); int fxFromName(const char*);
```
`storage.h`: `void loadSign(SignState&); void saveSign(const SignState&);` — one `putBytes("sign", &s, sizeof s)` in namespace `sign` with a version byte prefix (`SIGN_BLOB_VER 1`) so a layout change in step 2 falls back to defaults instead of reading garbage. `bool loadSsid(char* out, size_t n, const char* def); void saveSsid(const char*);` in `sys`.

### R2. `hub.h/.cpp` additions
Struct for per-board telemetry, replacing the three parallel arrays:
```cpp
struct BoardInfo {               // indexed by pos 1..MAX_BOARDS, zero = never heard
  uint32_t lastHb;               // millis of last HB (age/online)
  uint32_t lastSeen;             // HELLO/ACK/HB (diagnostics only)
  int8_t   rssi;  uint16_t mv;  uint8_t shownChar; uint8_t nodeState; uint16_t lastShowSeq;
};
static BoardInfo info[MAX_BOARDS + 1];   // guarded by tMux like table[]
```
`handlePacket`: `case HB:` → `portENTER_CRITICAL(&tMux); BoardInfo& bi = info[p]; bi.lastHb = bi.lastSeen = millis(); bi.rssi = rssi; bi.mv = hb->vbat_mV; bi.shownChar = hb->shownChar; bi.nodeState = hb->state; bi.lastShowSeq = hb->lastShowSeq; portEXIT_CRITICAL(&tMux);`. HELLO/ACK update `lastSeen` only (and `rssi`). `onResetOrd`/`onForget` zero the entry.

Live sign state and the handover (set-flag/copy pattern, as `node.cpp` does for `latestShow`):
```cpp
static SignState live;                 // core 1 only (tick/render/sendShow)
static char      liveChars[MAX_BOARDS];
static SignState pending; static volatile bool pendingFlag = false;
static portMUX_TYPE signMux = portMUX_INITIALIZER_UNLOCKED;
static uint32_t dirtyAt = 0;           // auto-save timer

void applySign(const SignState& s) {   // any core
  portENTER_CRITICAL(&signMux); pending = s; pendingFlag = true; portEXIT_CRITICAL(&signMux);
}
SignState sign() { SignState c; portENTER_CRITICAL(&signMux); c = pendingFlag ? pending : live; portEXIT_CRITICAL(&signMux); return c; }
// in tick(), first thing:
if (pendingFlag) { portENTER_CRITICAL(&signMux); live = pending; pendingFlag = false; portEXIT_CRITICAL(&signMux);
                   signLayout(live, liveChars); showSeq = showSeq + 1; scheduleBurst(); dirtyAt = millis(); }
if (dirtyAt && millis() - dirtyAt >= 2000) { storage::saveSign(live); dirtyAt = 0; Serial.println("[HUB] sign saved"); }
```
`sign()` reads `live` on core 0 while core 1 may write it on the swap; to keep it strictly safe, do the swap *and* the `live` read both under `signMux` (as shown). `saveNow()` for the `save` command sets `dirtyAt = 1` (forces a save next tick on core 1 — NVS writes stay off the net task).

`sendShow`: `s.r/g/b = live.r/g/b; s.brightness = signBriEff(live); s.effect = live.effect; s.effectPeriodMs = live.effectPeriodMs; s.numBoards = live.boards ? live.boards : highestOwned(); memcpy(s.chars, liveChars, MAX_BOARDS);` and on a non-periodic send: `Serial.printf("[SHOW] seq=%u color=%02X%02X%02X bri=%u fx=%u\n", …)` (B4).

`uint8_t numBoardsEffective()`; `bool identifyPos(uint8_t pos, uint16_t ms)`; `bool forgetPos(uint8_t pos)` (S3-25); `void buildState(JsonObject root)` (S3-14) — copies `table[]` and `info[]` under `tMux` into locals, then writes `cfg` (from `sign()`; `briEff`, `fx` name, `boardsAuto = boards==0`, `name` from the SSID the radio started with, `fw`) and `state` (hub first with `self:true`, then table entries sorted by pos). `char` for a node = `info.shownChar` (what the node *reports*), for the hub = its own rendered char; printable via `symbolName()` → `"{heart}"`, else the 1-char string, else `""`.

`render()` uses the shared styling function (R4) with `live` and `hubNow() = millis()`.
