# Review — Phase 1 step 1 draft (`firmware/LED_Sign_Mesh/`, Qwen draft 1)

Reviewed against: `docs/build-briefs/PHASE1_STEP1_radio_and_numbering.md`, `docs/PROJECT_PLAN.md` §2.1/2.3/3/4.1/5, `firmware/bench/espnow_ping/espnow_ping.ino`. Draft read from the Qwen box (`~/esp32-led-sign/firmware/LED_Sign_Mesh/`), compile log `/tmp/mesh_build1.log` (arduino-cli stopped after display.cpp / node.cpp / FastLED.h; hub.cpp, radio_espnow.cpp and the link stage were never reached, so the log under-reports).

Toolchain: core 3.3.12 / IDF 5.5.5, FastLED 3.10.9, LOLIN32 `no_ota`.

## Verdict

**NOT MERGEABLE — 14 blocking, 17 major, 14 minor.**

The draft has a reasonable file layout, correct packed protocol structs and a radio init sequence that follows `espnow_ping`, but it does not compile (6 distinct error classes, only 3 of which are in the log) and, once it compiles, it cannot pass A2: `radio::pump()` discards every received packet, the hub never adds a node as a peer, every save to NVS silently fails, and all packets carry `seq = 0` so the node's own dedupe drops every Show after the first. Acceptance A2–A6 all fail as written.

## Findings

Severity: **blocking** = will not compile or defeats A1/A2 outright; **major** = acceptance test or plan §3 behaviour fails; **minor** = quality/robustness.
