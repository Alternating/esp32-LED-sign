# Review — Phase 4 draft (hub-hosted OTA, Qwen draft 1)

Reviewed against: `docs/build-briefs/PHASE4_OTA_hub_hosted_updates.md` (Core design, scope items 1–10, acceptance O1–O10), `docs/PROJECT_PLAN.md` §2.3/§7, the verified baseline in `firmware/LED_Sign_Mesh/` (commit `b7ea985`; `STEP{1,3,2}_VERIFICATION.md`), the established concurrency pattern (`STEP3_REVIEW.md` "Refactor disposition", `STEP2_REVIEW.md`: core-0 handlers write pending copies under a portMUX, core 1 applies; `FastLED.show()` only in `loop()`; `esp_now_send` only from `radio::pump()`). Draft read from the Qwen box at `~/esp32-led-sign/drafts/ota_qwen_v1/`; compile log `build1.log` (19 errors, `PartitionScheme=min_spiffs`).

Toolchain facts checked on the box (core 3.3.12 / IDF 5.5.5):

- **`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`** and `CONFIG_APP_ROLLBACK_ENABLE=y` in `~/.arduino15/packages/esp32/tools/esp32-libs/3.3.12/sdkconfig` (lines 286, 3484; `ANTI_ROLLBACK` not set). The sdkconfig is **not** at `tools/sdk/esp32/sdkconfig` in core 3.x. So IDF rollback is available — **but** the Arduino core *auto-confirms* a pending image during `initArduino()`: `cores/esp32/esp32-hal-misc.c:319-333` calls `esp_ota_mark_app_valid_cancel_rollback()` on `ESP_OTA_IMG_PENDING_VERIFY` unless the weak C hook **`bool verifyRollbackLater()`** (line 290) returns `true`. Our sketch must define `extern "C" bool verifyRollbackLater() { return true; }` and confirm later itself (§R5). Without that override the 30 s health window is a no-op. IDF semantics: the bootloader rolls back after **one** unconfirmed boot (PENDING_VERIFY → ABORTED on the next reset), not after three; a power cycle inside the 30 s window also rolls back. O7 must be reworded accordingly.
- `min_spiffs.csv`: `app0` 0x10000 / **0x1E0000 (1 966 080 B)**, `app1` 0x1F0000 / 0x1E0000, `spiffs` 0x3D0000 / 0x20000, `coredump` 0x3F0000. The step-3 app was 1 072 659 B (`no_ota`); +OTA/HTTPClient/Update code lands around 1.15 MB — fits with ~0.8 MB headroom. `boot_app0.bin` (otadata) still goes at 0xE000 in the merged image.
- Available and verified in headers: `WebServer::on(uri, method, fn, ufn)` + `upload()` → `HTTPUpload{status,buf,currentSize,totalSize}`; `NetworkServer::accept()` (`available()` is deprecated → warning, violates O1); `Update.begin(size|UPDATE_SIZE_UNKNOWN)`, `write`, `writeStream`, `end(true)`, `abort`, `progress()`, `errorString()`, `canRollBack/rollBack`; `HTTPClient::begin(NetworkClient&, String url)`, `GET()`, `getSize()`, `getStreamPtr()`, `setTimeout(uint16_t)`, `setConnectTimeout`, `setReuse(bool)` (no `setReuseConnection`); `esp_image_verify(ESP_IMAGE_VERIFY_SILENT, &pos, &meta)` → `meta.image_len` (bootloader_support, linked into apps); `esp_app_get_description()->app_elf_sha256`; `WiFi.softAPmacAddress(uint8_t*)`.

What the draft changed vs the baseline (by `diff`): **new** `ota.h/.cpp`, `build_id.h`; **modified** `config.h` (+7), `protocol.h` (PROTO_VER 2, buildId in Hello/Hb, OtaEnter/OtaStatus), `hub.h` (no change despite the diff list), `node.h` (+OTA state), `hub.cpp` (+buildId plumbing, two switch cases, `hubBuildOtaState` call), `node.cpp` (+OTA_ENTER case, tick/render dispatch), `commands.cpp` (+3 commands), `transport_web.cpp` (+/ota, /ota_status, fw server task), `LED_Sign_Mesh.ino` (comment + include only), `radio_espnow.cpp` (max_conn), `make_images.sh` (FQBN comment, build_id.h), `web_page.h` (regenerated from the 177-line sketch, must not be used). `index_draft.html` is a from-scratch rewrite of the page (ES2017, `innerHTML` with template literals, no tabs, no symbol keypad, no debounce) — treat as a sketch of the Firmware section only.

## Verdict

**NOT MERGEABLE — 26 blocking, 14 major, 6 minor. The draft is a skeleton: it does not compile (19 errors + 2 warnings, and more hidden behind them), and once it did, no node could ever be updated: `OTA_ENTER` is 88 B and `radio::send()` refuses anything over `MAX_FRAME` (64), `ota_nodes` queues nothing (it compares the hub's buildId with itself), the fw server streams raw flash with no HTTP response line to a client that speaks HTTP, the node's download loop misreads `WiFiClient::read()`'s `-1` as 4 GB of data, and the node blocks the core-0 radio pump for up to 5 s inside `handlePacket()`. Rollback is a pair of NVS helpers nobody calls, with no `verifyRollbackLater()` override, so the Arduino core confirms every new image at boot. Nothing in `hub::tick()` drives the queue, so the 120 s timeout can only fire when a packet happens to arrive.**

Also a hard regression: `PROTO_VER` was bumped to 2 but `radio_espnow.cpp:68` still drops any frame whose `ver != PROTO_VER`, so the "v1 tolerance" the brief asks for is impossible at the layer the draft left untouched, and a v2 hub and v1 node are mutually deaf.

The good parts, to keep: the protocol struct layouts (`OtaEnter`, `OtaStatus`, `buildId[4]` appended to `Hello`/`Hb`), the `BoardInfo.buildId` plumbing in hub.cpp (HELLO + HB under `tMux`, status line), the `commands.cpp` additions (shape and arg checking match the house style), `MAX_CONN` into the single `softAP` call, the hub-side `/ota_status` JSON fallback handler (useful for O10), the queue record shape (`mac,pos,state,pct,startedAt,failMsg`), the `pct % 5` reporting intent, and the Firmware-section HTML fragment in `index_draft.html` (file input, upload button, progress div, queue list, `fw-badge.bad`).

## Refactor plan

Refactor against the verified baseline (`b7ea985`), not by patching the draft. Keep ota.h small and JSON-free; the hub queue lives in hub.cpp (it needs `table[]`/`info[]`/`tMux`), the node state lives in node.cpp, ota.cpp holds the role-independent mechanics.

### R1 — Hub fw server (ota.cpp, hub only)

```cpp
// ota.h
namespace ota {
  void        begin();                       // buildId + imageLen (esp_image_verify SILENT, ~150 ms, once)
  const uint8_t* buildId();                  // 4 bytes of app_elf_sha256
  void        buildIdHex(const uint8_t* id, char out9[9]);
  const char* versionStr();                  // FW_VERSION_STR
  const char* gitStr();                      // BUILD_GIT
  const char* slotName();                    // running partition label ("app0"/"app1")
  uint32_t    imageLen();                    // exact running image length (served size)
  bool        pendingVerify();               // running image still ESP_OTA_IMG_PENDING_VERIFY
  void        tick(bool healthy);            // confirm image after OTA_VERIFY_MS when healthy (R5)
  void        startFwServer();               // hub: WiFiServer(OTA_PORT) task, core 0
  void        stopFwClient();                // hub cancel: drop the active download
  uint32_t    fwServed();                    // bytes served in the current/last transfer (status)
}
```

`fwServerTask`: `xTaskCreatePinnedToCore(task, "fw", 8192, nullptr, 1, &h, 0)`. Loop: `NetworkClient c = srv.accept(); if (!c) { delay(20); continue; }` → `c.setTimeout(2000)`; read request until blank line (bounded 512 B, 1 s); if method/path is not `GET /fw.bin` → `404` + close. Write header `HTTP/1.0 200 OK\r\nContent-Type: application/octet-stream\r\nContent-Length: %u\r\nConnection: close\r\n\r\n`. Body: `esp_partition_mmap(part, 0, imageLen, ESP_PARTITION_MMAP_DATA, &p, &hnd)` once at `begin()` (keep mapped); `while (off < len && c.connected() && !cancel) { n = min(2048, len-off); w = c.write(p+off, n); if (w <= 0) break; off += w; }`; `c.stop()`. Fallback when mmap fails: static `uint8_t buf[2048]` + `esp_partition_read`. No display, no radio, no JSON from this task. `cancel` is a volatile flag set by `stopFwClient()`.

### R2 — Node OTA (node.cpp owns the state, ota.cpp owns the transfer)

```cpp
// ota.h (node)
struct NodeOtaProgress { volatile uint8_t pct; volatile uint8_t result; char msg[24]; };  // result: 0 running,1 ok,2 failed
bool nodeOtaStart(const OtaEnter& e);   // spawns otaTask (core 0, 8 kB, prio 1); false if already running
const NodeOtaProgress& nodeOtaProgress();
```

- `node::handlePacket` (core 0): `case OTA_ENTER:` if `len >= sizeof(OtaEnter) && dstPos == myPos`: `learnHub(srcMac); sendAck(OTA_ENTER, seq);` if `st == OTA` → return (retry); else copy the frame into `pendingOta` under `showMux`-style `otaMux`, set `otaReqFlag`.
- `node::tick` (core 1): sees `otaReqFlag` → `setState(OTA)`, `otaEnteredAt = now`, `otaStartAt = now + 150` (lets the pump send the ACK). At `otaStartAt`: `ota::nodeOtaStart(pendingOta)`. In `OTA`: no HELLO/HB, LOST_HUB timer suspended; every 5 % change → `sendOtaStatus(pct, DOWNLOADING)` (unicast `hubMac`, `srcPos = myPos`, `radio::send` enqueues — pattern-safe); `result == ok` → `sendOtaStatus(100, VERIFIED)`, hold a full bar 500 ms, `ESP.restart()`; `result == failed` or `now - otaEnteredAt > OTA_NODE_TIMEOUT_MS` → `sendOtaStatus(pct, FAILED, msg)`, `WiFi.disconnect(false); esp_wifi_set_channel(ESPNOW_CHANNEL, WIFI_SECOND_CHAN_NONE);` `setState(DISCOVER)`.
- `otaTask` (core 0): `WiFi.setSleep(false); WiFi.setAutoReconnect(false); WiFi.begin(ssid, pass, ESPNOW_CHANNEL, bssid);` wait ≤ 8 s for `WL_CONNECTED` (`delay(50)` polls) else fail "join"; `NetworkClient cl; HTTPClient http; http.setConnectTimeout(5000); http.setTimeout(10000); http.setReuse(false); http.begin(cl, IPAddress(e.ip).toString(), e.port, "/fw.bin");` `GET() == 200` and `getSize() == e.size` else fail "http %d"; `Update.begin(size)` else fail `errorString()`; stream loop as in O4-31 with 4 kB static chunk, no-progress watchdog 10 s, update `pct`; `Update.end(true)` else fail; `http.end(); result = ok; vTaskDelete(nullptr)`. On any failure: `Update.abort(); http.end(); result = failed; vTaskDelete(nullptr)`. The task never touches `display::`, never calls `esp_now_send` (statuses are sent from `tick()`).
- Render (`node::render`, `OTA` case): `display::clear(); display::renderDigit(myPos, CRGB(0,0,255));` bar: `for col in 0..19: lit = col < pct*20/100; for row in 18,19: leds[ledIndex(row,col,mirror)] = lit ? CRGB(0,255,0) : CRGB::Black;` (digit glyph occupies rows ≤ 17 per `character_patterns.h`; verify the 20×20 digits do not reach row 18 — if they do, dim rather than clear). `display::show()` stays in `loop()`.
- `handlePacket` in `OTA`: accept `OTA_ENTER` (re-ACK) and `SHOW` (clock only); drop ASSIGN/SETPOS/IDENTIFY/FORGET/SETMIRROR.

### R3 — Hub queue (hub.cpp)

```cpp
enum class OtaRow : uint8_t { QUEUED, SENT, UPDATING, REBOOTING, DONE, FAILED, SKIPPED_OFFLINE };
struct OtaEntry { uint8_t mac[6], pos, pct; OtaRow st; uint32_t startedAt; char msg[24]; };
static OtaEntry otaQ[MAX_BOARDS]; static uint8_t otaQLen, otaCur /*index+1, 0 none*/; static uint8_t otaReq /*0 none,1 all,2 one,3 cancel*/, otaReqPos;
```

All under `tMux`. `hub::otaNodes()/otaNode(pos)/otaCancel()` (called from commands, any core) set `otaReq`. `tick()`: `otaReq` → build queue from `table[]`+`info[]` snapshot (online = `lastHb` within `OFFLINE_AFTER_MS`; needs update = `memcmp(info[pos].buildId, ota::buildId(), 4) != 0`); start next: fill `OtaEnter{ssid=radio::apSsid(), pass=AP_PASS, bssid=softAPmacAddress, ip=softAPIP, port=OTA_PORT, buildId, size=ota::imageLen()}`, `radio::send(mac, &e, sizeof e, true)`, `st = SENT, startedAt = now`. Completion: in `handlePacket` HELLO/HB case, if the MAC equals `otaQ[otaCur].mac` and the frame's buildId equals ours → `DONE`. `OTA_STATUS` (matched by srcMac): `pct`, `UPDATING`, `REBOOTING` on VERIFIED, `FAILED` + msg. Timeout `now - startedAt > OTA_NODE_TIMEOUT_MS` → `FAILED "timeout"`. Cancel → `ota::stopFwClient()`, remaining `QUEUED` rows dropped, current → `FAILED "cancelled"`. Serial: `[OTA] queue: pos 5 (buildId 1a2b3c4d → 9f8e7d6c)`, `[OTA] pos 5 42 %`, `[OTA] pos 5 done in 31 s`.

`buildState`: `root["ota"]` = `{hub:{buildId,version,git,slot,pendingVerify,imageLen}, queue:[{pos,state,pct,msg}], current:{pos,pct,state}|null}`; each board row gets `fw` (8 hex; `"00000000"` when unknown).

### R5 — Rollback (IDF, confirmed by sdkconfig)

- `extern "C" bool verifyRollbackLater() { return true; }` in ota.cpp (the hook is a weak **C** symbol in `esp32-hal-misc.c`; a C++-mangled definition would not override it).
- `ota::tick(healthy)` from `loop()` (both roles): once, when `pendingVerify() && millis() >= OTA_VERIFY_MS && healthy` → `esp_ota_mark_app_valid_cancel_rollback()`, `Serial.println("[OTA] image confirmed (rollback cancelled)")`. Hub healthy = `hub::state() == RUNNING` and `WiFi.softAPgetStationNum() >= 0` (AP up — `radio::beginHub` returned true); node healthy = `node::state() == RUNNING` (it has received a Show). `#ifdef OTA_SELFTEST_FAIL` → `if (pendingVerify() && millis() > 10000) ESP.restart();`.
- Behaviour to document (O7): a bad-but-bootable image is rolled back by the bootloader on the **first** reset without confirmation (power cycle, panic, WDT). Message on boot after rollback: check `esp_ota_get_state_partition(other) == ESP_OTA_IMG_ABORTED` and log `[OTA] previous image app1 rolled back`. `/state.ota.hub.pendingVerify` is true during the window; the UI shows "verifying… (Ns)".
- Node side: same mechanism; a node that fails to reach RUNNING within 30 s after OTA reboots (WDT/power) → bootloader restores the old image → it rejoins with the old buildId → hub shows it as needing update again (visible, correct).

**Interpretations for the verifier**
- O7 as reworded by the review: an unconfirmed image rolls back on **one** reset, not three. A wired install (blank otadata) boots app0 with no otadata entry (`state=n/a`), so it is never "pending".
- Node health "reached RUNNING or DISCOVER": a node rebooted into a new image confirms at 30 s if it is RUNNING (normal) or still DISCOVERing; if it is LOST_HUB at 30 s it confirms later, once it reaches RUNNING. A reset before confirmation rolls it back.
- `ota_node` on an up-to-date board is refused (`up_to_date`) rather than re-flashing the same image.
- While a node downloads it sends no HB, so the Boards tab shows it offline; the Firmware table shows its OTA status.
- The hub's `/ota` upload blocks the port-80 server (single-threaded) for the transfer; the page pauses `/state` polling while uploading and resumes after the reply. ESP-NOW keeps running (radio pumped per chunk).
- The status table merges `err` into the status cell (`failed: timeout`) to fit a phone; columns are Pos / fw / Status / % / Update.

**Not verified (needs hardware):** everything in O2–O7, O9, O10 and bench B1–B8 except B8. In particular: `esp_image_get_metadata().image_len` must equal the `.bin` file size (1 137 136 B for `8a36995`); the hub logs it at boot.
